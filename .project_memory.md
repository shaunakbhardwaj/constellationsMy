# Project Memory

## Purpose

This is the running project-memory file.

Use it for:

- current state
- major product decisions
- active TODOs
- open questions
- next milestones

This file should be easy to append to after every meaningful run.

---

## How To Use This File

### `Decisions`

Use for choices that are considered locked unless someone explicitly reopens them.

Examples:

- product direction
- architecture choice
- UX pattern
- persistence model
- integration strategy

### `In Progress`

Use only for work that is actively underway or has already started materially.

That means at least one of these is true:

- code has already been written
- a plan/spec is detailed enough that implementation is imminent
- the work is currently the active focus of the project

Do **not** put loose ideas or someday-maybe features here.

Good examples:

- "branch brief editing UI"
- "replace clipboard Codex handoff with real integration"
- "artifact detail panel"

Bad examples:

- "maybe support spreadsheets"
- "could add collaboration someday"

### `Open Questions`

Use for unresolved decisions that matter and still need a call.

These should be questions whose answers would change:

- scope
- implementation
- UX
- architecture

### `Next Milestone`

Use for the single most important near-term shipping target.

This should be concrete enough that another agent could pick it up immediately.

### `Backlog`

Use for relevant future work that is not active yet.

## Current Product Direction

`Flows` is no longer being treated as an "AI mindmapping app."

Current direction:

- ingest prompt, pasted text, or PDF
- compress into a navigable map
- deepen branches with thinking lenses
- select a path
- generate a branch brief
- dispatch that brief to Codex

Primary audience:

- builders
- operators
- founders
- PMs

Core promise:

**From overwhelming text to a chosen path to action.**

---

## Major Decisions Locked In

1. Remove top-level document modes from the product model.
2. Use source-first ingestion:
   - Ask
   - Paste
   - Drop PDF
3. Replace document modes with branch-level thinking lenses:
   - Expand
   - Deep Dive
   - Questions
   - Devil’s Advocate
4. Make branch selection a first-class interaction.
5. Use branch briefs as the first execution artifact.
6. First paired integration is Codex only.
7. Persist sources, maps, and artifacts separately.
8. Keep legacy documents readable during migration.
9. Default model provider is Ollama local, with OpenRouter kept as an explicit hosted-model option.
10. Generated node titles should stay concise, while full node context is stored separately as `description`.
11. Codex integration should support both clipboard handoff and direct local `codex exec`.
12. The primary Flows UI should use a warm monochrome design system: off-white light mode, warm off-black dark mode, Outfit + JetBrains Mono typography, and no blue/purple gradient AI-dashboard styling.
13. Mind map transient UI state should not trigger full D3 graph rebuilds; selection/focus/expansion styling belongs in lightweight in-place updates, while menus and edit inputs stay layered over the durable canvas.
14. Mind map menus should anchor from node layout plus the current or target zoom transform, not from stale pointer-event coordinates.

- no branch-brief editing UI
- no artifact detail pages
- no checklist artifact
- no flowchart artifact
- no advanced PDF structure extraction
- no include/exclude subtree controls in selection mode
- no citations/backreferences from brief to source text spans
- no log filtering or search in diagnostics yet
- no redaction/privacy controls for stored LLM prompts and responses yet
- no automated interaction coverage for D3 mind map flows such as node-to-node retargeting, inline edit commit, and deleting focused branches
- secondary UI surfaces such as Settings, Diagnostics, notes, and delete confirmation still need a full design-system polish pass
- lint cannot currently run because ESLint 9 needs a repo-level `eslint.config.*` file
